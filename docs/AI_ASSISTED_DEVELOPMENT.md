# AI 辅助开发生产规范

本项目使用 Codex 辅助分析、实现、测试和代码审查。Codex 是受约束的开发助手，
不是发布审批人，也不能替代开发者对业务、数据和生产变更的最终负责。

## 已提交的配置

| 文件 | 用途 |
| --- | --- |
| `AGENTS.md` | Codex 的仓库级工程约束 |
| `docs/AI_HARNESS.md` | Codex 的风险路由、策略检查和交付协议 |

个人配置、登录信息、模型选择和本机目录不要提交。Codex 的个人偏好应放在用户
目录下的配置或全局 `AGENTS.md`，不要写进项目规则。

## 推荐启动方式

在仓库根目录启动工具，并使用需要人工确认的默认权限模式。需要自动化运行
时，应放在隔离容器或临时工作树中，并先确认工作区、凭据和网络边界：

```bash
codex -C /Users/han/github/demeter -s workspace-write -a on-request
```

不要在生产服务器、含有生产凭据的目录或未审查的共享工作区中运行具有自动
批准、绕过沙箱或全盘访问权限的 Codex 模式。项目规则不会替代组织级
MDM/托管策略。

## 任务流程

1. 先描述目标、影响范围、验收标准和不做的事情。
2. 先读相关代码、测试、配置和当前 Git 状态，再提出最小实现方案。
3. 修改后先运行聚焦测试，再运行完整验证；涉及后端发布边界时必须运行
   `backend/scripts/release-preflight.sh`。
4. 检查 `git diff --check`、敏感文件扫描和最终差异，确认没有生成物、密钥
   或无关格式化变更。
5. 由开发者审查业务逻辑、权限、数据访问、迁移和用户体验后，才允许合并。
6. 提交、推送、发布、数据库迁移、云资源变更和生产数据操作必须由人明确
   批准，并保留审计记录。

仓库级的风险路由、自动策略检查和交付证据模板见
[`AI_HARNESS.md`](AI_HARNESS.md)。每次交付前先执行
`sh scripts/ai-harness-preflight.sh <base-ref>`；后端改动可执行
`sh scripts/ai-harness-verify.sh <base-ref>` 获取对应的自动验证闭环。

## 数据和提示词边界

- 不把微信 `AppSecret`、数据库密码、阿里云凭据、访问 Token、私钥、生产
  数据、用户图片或日志中的个人信息粘贴到提示词、Issue、聊天记录或外部
  模型服务中。
- 调试必须使用脱敏和最小化样本；OCR 原图默认视为敏感业务数据。
- 不要求 AI 读取 `.env`、密钥目录、生产备份、云控制台导出文件或完整日志。
- 外部联网、安装依赖、上传代码或调用 MCP/插件前，应确认数据是否会离开
  受控环境以及供应商的保留策略。

## 生产代码门禁

- 后端所有业务用例继续通过责任链执行，handler 顺序、失败策略和事务边界
  必须有测试覆盖。
- 保持租户隔离、幂等键、审计、限流、错误脱敏、健康检查和生产启动校验。
- 数据库变更只允许追加 Flyway migration；生产运行进程不能自动改表。
- OCR 供应商只能实现 `HandwrittenBillOcrProvider`，供应商异常必须转换为
  稳定错误分类，不得把供应商响应体或凭据写入任务、审计或日志。
- 小程序页面保持 Safe Area、设计稿布局和服务层边界；不能为了通过模拟器
  而绕过真实交互状态或错误状态。

## 发布前人工检查

AI 工具完成代码后，发布人至少要确认：

- 测试、构建、生产预检和必要的 MySQL 集成验证均通过。
- 依赖、容器、密钥扫描和权限检查均通过。
- 数据库备份、迁移顺序、回滚兼容性和恢复方案已经确认。
- readiness、错误率、延迟、连接池、队列积压和审计指标有明确观察方式。
- 变更说明、风险、验证证据和未完成的现场检查已记录。
