# Demeter AI Coding Harness

本仓库的 AI coding harness 把模型、仓库上下文、权限、验证和人工审批组成
一个可重复执行的交付闭环。它服务于 Codex，不授权工具绕过生产边界，也不替代
发布人。

## 执行入口

| 工件 | 责任 |
| --- | --- |
| `AGENTS.md` | Codex 的架构、安全、数据和交付约束 |
| `scripts/ai-harness-preflight.sh` | 只读策略检查、风险分类和验证建议 |
| `scripts/ai-harness-verify.sh` | 根据变更范围执行后端自动验证 |
| `.github/workflows/ai-harness.yml` | CI 中独立运行的仓库级策略门禁 |
| `.github/pull_request_template.md` | 人工审查和证据记录模板 |

从仓库根目录执行。`<base-ref>` 通常为 `HEAD`；在审查已提交分支时可指定
共同祖先提交。

```bash
sh scripts/ai-harness-preflight.sh <base-ref>
sh scripts/ai-harness-verify.sh <base-ref>
```

`preflight` 不读取环境文件、凭据或生产数据。它会检查空白差异、敏感路径、
Flyway 追加式迁移、小程序页面边界和关键业务用例的责任链依赖，并输出风险级别
对应的验证要求。`verify` 在后端变更时执行 Maven 验证；高风险后端变更改为执行
已有的发布预检。小程序的编译与交互验证必须由微信开发者工具完成，不能伪造成
自动化通过。

## 风险路由

| 变更 | 自动验证 | 必须补充的证据 |
| --- | --- | --- |
| 普通后端实现或测试 | Maven `clean verify` | 聚焦测试及行为说明 |
| 安全、配置、责任链、支付、OCR、迁移、生产容器 | `release-preflight.sh` | 聚焦边界测试、迁移/运行时风险说明 |
| 小程序页面、组件、服务层 | 静态页面边界检查 | 开发者工具编译和五种 UI 状态截图/记录 |
| 文档或 AI 配置 | 策略预检 | 规则一致性人工审查 |

高风险代码不能通过删减认证、租户隔离、幂等、审计、限流、健康检查或迁移校验来
换取测试通过。OCR 实现仍必须停留在 `HandwrittenBillOcrProvider` SPI 边界内。

## 代理工作协议

每个 AI 任务在修改前应明确：目标、影响路径、验收条件、非目标和风险等级。代理
先读取相关源码、测试与 Git 状态；只在授权的工作区内改动；失败时保留失败证据并
定位原因，不能用跳过测试、放宽断言或关闭安全检查作为恢复策略。

交付必须包含下列内容：

- 行为变化和未改变的边界。
- 已执行命令及结果，以及未执行项的环境原因。
- 高风险变更的租户、幂等、审计、迁移、认证和回滚兼容性结论。
- 小程序变更的加载、空数据、失败、保存中、Safe Area 验证结论。
- `git diff --check` 与最终差异审查结果。

提交、推送、发布、迁移、云资源变更和生产数据操作仍需人明确批准。AI 可以准备
证据，不能代表人执行审批。
