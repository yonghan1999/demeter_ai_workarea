# OCR 任务运营

## 用户流程

小程序支持拍照或从相册选择图片，创建任务后在 OCR 任务列表查看进度；识别完成进入复核页，低可信字段和重复账单会被标记，确认后可合并为正式账单。

开始识别前可填写最多 500 字的“识别补充说明”，例如列顺序、简称或容易混淆的字；不填写也可识别。说明随当前任务保存，自动和手动重试均沿用原说明，不会加入租户历史词典。模型只将说明作为视觉消歧参考，仍以图片为依据，缺失或无法辨认的字段留空，用户应复核结果。

同一设备、同一账号下，开始识别时会记住本次说明，下次打开新建识别页自动回显，可修改或清空。上传失败仍保留本次说明；清空后提交，下次也回显为空。该偏好按租户和用户隔离，仅保存在本地，不跨设备同步；本地缓存不可用时仍可正常上传。

识别 Worker 会向模型提供当前租户最近 10 次识别任务中的非空历史说明，帮助模型理解该客户对人名、地址/起终点、车型和货物的称呼及版式习惯。历史说明只作为示例，仍必须以当前图片的位置和字形证据为准，不会直接填入当前账单。

上线前先由专用 Migrator 执行 V24 迁移，再启动 API 和 Worker；最低数据库版本为 24。说明会随图片发送至现有千问服务，最多增加 500 字输入，无新增依赖或外部服务；不要填写与账单无关的敏感信息。

## 后端状态机

`pending → processing → succeeded`；失败任务进入 `failed`，重试时为 `retrying` 后再次处理。上传接口返回 `202 Accepted` 和任务地址，查询接口按任务 ID 获取结果。

## 异常处理

- 未配置供应商：生产 Worker 会拒绝启动；本地一体化环境中的任务会进入
  `failed/OCR_NOT_CONFIGURED`，不会写入正式账单。
- 供应商限额：任务失败码为 `OCR_PROVIDER_QUOTA_EXCEEDED`，检查额度和限流后重试。
- 认证失败：核对 API Key 与 Endpoint 是否同地域；不要在日志或工单中提交密钥。
- 任务积压：观察租约和 Worker 日志，先确认供应商限流，再扩容 Worker。
